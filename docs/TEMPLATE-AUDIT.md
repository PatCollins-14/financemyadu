# Template audit

Audited 2026-10-23. Template = a copy of the single-file landing page built earlier in this conversation (`C:\Users\keine\adu-landing\index.html`), saved here unchanged as `src/template-original.html`. Nothing in the original folder was changed.

## 1. Framework, tooling, commands
- **Framework:** none. One static `index.html` with inline CSS and one inline `<script>`.
- **Language / build tool / package manager:** none. There is no `package.json`, no bundler, no lockfile.
- **Machine tooling found:** `git`, `curl`, `perl` (from Git for Windows), Windows PowerShell 5.1. Node, npm and Python are **not** installed (the `python.exe` on PATH is the Windows Store stub). Nothing was installed globally.
- **Dev/run:** open the file, or any static file server. **Build:** none existed.
- **What this build adds:** a small PowerShell static-site builder (`scripts/build.ps1`) and PowerShell preflight (`scripts/preflight.ps1`), wrapped by `run.cmd`. See DECISIONS D2.

## 2. Rendering mode (tested)
- **Static HTML**, but **part of the content is client-side only.** Test: the raw file contains one `<h1>` and the hero, trust strip, careful, financing, why-us, income-header, steps and CTA sections as plain HTML. The six ADU-type cards, four income cards, six project tiles, six reviews, and all icons are created by JavaScript (`innerHTML`) and are **absent from the raw HTML**. `<a href>`s to `tel:` are fine; the quiz-less form works only through JS (`preventDefault`, no `action`, no `method`).
- **Stop condition (a)** does not apply: the template is not a client-side-only app, and it is small enough that the new build can emit real HTML for every section. The new build renders everything at build time.

## 3. Structure, styling, tokens
- Single file: `<style>` (about 330 lines) then body sections then `<script>` (CONFIG, icons, SVG generators, form handler).
- **Tokens (`:root`):** `--blue #007bc3`, `--blue-dark #0a5f9a`, `--blue-deep #0071c8`, `--orange #f27926`, `--ink #1c2430`, `--text #3c4858`, `--muted #6b7686`, `--line #dfe6ec`, `--soft #f5f9fa`; fonts Playfair Display (headings) and Inter (body).
- **Layout:** sticky dark top bar, hero with form card, blue trust strip, alternating white/soft sections, 3-6 column card grids, 5-step timeline, footer, mobile sticky call bar. Light single theme by design, `color-scheme: light`.
- **Brand comparison (letstalkhomemortgage.com):** site CSS uses blues `#52afe6`, `#354982`, `#223d78`, `#172338`, gold `#f0b82e`, orange logo; fonts Manrope, DM Sans, Space Grotesk. The template blue family is close; Playfair headings are different from the site's sans look. **Decision:** keep the template's layout, components and type pairing, re-point color tokens to the site's blues so the funnel and hub look like one family (DECISIONS D4).

## 4. Pages, routes, forms, images, metadata
- **Routes:** one page only (`/`). **Form:** client-side validation, posts JSON to `CONFIG.formEndpoint` if set, otherwise logs to the console. No no-JS fallback. **Images:** none (inline SVG illustrations generated by JS). **Metadata:** `<title>` and `<meta name="description">` only.

## 5. Existing SEO, analytics, consent, sitemap, robots, schema
None. No canonical, no robots meta, no Open Graph, no JSON-LD, no sitemap, no robots.txt, no analytics, no cookie banner.

| 2 | Six invented reviews, "Rated 4.9/5 by 115+ homeowners" | No fabricated reviews or ratings |

| 7 | Form with no consent checkbox, no privacy link, console-log "demo mode" | Consent and honest handling required |
| 8 | No identifiers, no Equal Housing, no NMLS footer | Compliance footer required |
| 9 | No robots/sitemap/canonical/noindex control | SEO foundation required |
| 10 | Scroll-reveal classes (`.rv`) | Content must be visible at rest (reveal class kept off) |

## 7. Adaptation plan
1. Keep the template's design system (tokens, type, spacing, card and band patterns) as `src/assets/site.css`; swap color tokens to the site blues; drop builder-specific components (project tiles, income photos).
2. Move all text to data (`config/`, `src/data/identity.json`, content files) and render every section to static HTML with `scripts/build.ps1`. JS is progressive enhancement only (quiz steps, consent toggle).
3. Funnel page = reworked hero + form card, rewritten sections from the build brief.
4. Hub = a second layout (article layout with byline, answer box, sections, sources, CTA).
5. Add robots, sitemap, canonical, JSON-LD, noindex flags, compliance footer, preflight, snapshots, WordPress exports.
